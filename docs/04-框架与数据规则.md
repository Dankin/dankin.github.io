# 04 框架与数据规则

## 1. 设计目标

1. 新增人物、物件、区域或故事，只改数据，不改引擎。
2. 故事从世界规则里涌现，不写成固定脚本，玩家乱试也能得到合理且好笑的反应。
3. "最后一步必须由本人迈出"是系统层硬规则，不靠故事自觉遵守。
4. 开放世界的"开放"来自密度和系统，面积后加。

## 2. 核心模型：现象 → 感知 → 反应 → 决心

1. **招式只产生现象，不直接改 NPC。** 风铃产生"声音"，路灯产生"光"，炉灶产生"香味"，气球产生"移动目标"。
2. **现象有类型、强度、范围、持续时间。** 声音随距离衰减，香味顺风飘，光被墙挡住。
3. **NPC 有感知，按性格对现象反应。** 胆小的人对突然的巨响会躲，对轻柔的前奏会放松。
4. **反应只改变 NPC 的内部状态。** 当"决心"累积到阈值，NPC 自己执行"迈出一步"。这是高光时刻，触发动画和音乐。

连锁无需单独编写：同一个现象会被多个 NPC 感知（面包香味飘过车站，画家就受影响）。

## 3. 数据表

所有表为配置文件（JSON 或 YAML），带 schema 校验，写错在启动时报错。

| 表 | 关键字段 |
|---|---|
| Tile 区块 | 外观、是否可行走、物件摆放点、所属区域 |
| Prop 物件 | id、外观、位置、招式列表、冷却、范围、可附身、风格标签 zh/western/mixed |
| Move 招式 | 产出的现象类型、强度、持续、动画、音效 |
| Stimulus 现象 | 类型：sound, light, scent, lure, block, company；强度、范围、衰减规则 |
| Interaction 相互作用 | 现象与现象/物件的组合规则（见下） |
| NPC | 外观、内核类型、日程、感知偏好、心结、暖度、吐槽库、口头禅库 |
| Story 故事 | 目标 NPC、阶段、解锁条件、奖励、内容层 main/side/ambient |
| Event 事件 | 彩蛋和沙盒的"条件 → 结果"规则 |
| Gag 笑点 | "物件×NPC"或"现象×现象"的特殊反应 |
| Weather 天气 | 对日程和现象的修正 |
| Pack 内容包 | 以上数据的集合，一个区域或一批新故事一个包，可独立启用 |

## 4. NPC 内部结构

| 字段 | 含义 |
|---|---|
| 内核类型 | 胆小、颓废、自强、开朗，决定使用哪个反应模板 |
| 暖度 | 0 到 100，驱动天色、灯光、帽子外观 |
| 心结 | 具体的卡点，有若干化解条件 |
| 决心 | 化解条件累积值，到阈值后 NPC 自己迈出一步 |
| 日程 | 按时段在哪里、做什么（首版为固定路线） |
| 感知偏好 | 对各类现象的敏感度，如阿福对"狗叫"高敏感 |
| 烦躁度 | 被同类现象反复打扰后上升，分三档：皱眉、吐槽、走开；冷却后恢复，不扣分 |

**暖度扩散**：帮助成功后，周围 NPC 暖度也会略升（香味让路人心情变好）。全镇总暖度决定天色、灯光、帽子外观。主线、支线、彩蛋共用这套进度。

## 5. 反应模板（按内核）

| 内核 | 模板 |
|---|---|
| 勇气 | 干扰多 → 清场或制造安静 → 给出"台阶"（安全的小开头）→ 本人迈出一步 |
| 振作 | 触发回忆（香味、旧物、熟悉的声音）→ 一次很小的成功体验 → 动力累积 → 本人重新开始 |
| 自强 | 让玩家看见他在努力 → 只清障碍，不替他做 → 他自己完成，玩家只能看 |
| 开朗 | 把已暖起来的 NPC 汇聚到同一场景，暖度互相放大 |

## 6. 相互作用表（系统化，首批）

| 组合 | 结果 |
|---|---|
| 热 + 雪人 | 融化成水，遇冷结冰 |
| 风 + 气球/纸片 | 被吹向风向 |
| 声音 + 动物 | 转头或跟来 |
| 光 + 雪 | 反光，可能晃到 NPC |
| 香味 + 动物 | 循着香味走 |
| 重物 + 冰面 | 打滑 |

新增物件只要声明它产出哪种现象，就自动进入这张表。

## 7. 玩家操作

1. 点击地面，帽子飘过去；无碰撞，带漂浮感。
2. 点击可附身物件，播放"钻进去"动画，附身该物件（无需走到旁边）。
3. 一次只能附身一个物件。
4. 附身后显示招式选项，通常 1 到 3 个。
5. 招式有简单冷却，不设能量条。
6. 再点地面或其他物件，离开并附身下一个。
7. 点 NPC 只能看气泡，不能附身，不能直接操作。
8. 手机和网页共用：只有点击和拖动。

## 8. 提示系统（保证不难）

| 卡住时间 | 提示 |
|---|---|
| 20 秒 | 相关 NPC 头顶气泡更明显 |
| 60 秒 | 帽子抖一下，指向关键物件 |
| 120 秒 | 高亮关键物件和招式，仍由玩家自己点 |

时间和强度是数据，可逐故事调整。`【待确认 Q10】`

## 9. 时间、存档、沙盒

- **时钟**：阶段内自动前进，玩家可停留；阶段锁防止信息过载。
- **沙盒**：通关后时钟固定在夜晚，所有内容开启，NPC 进入日常循环。
- **存档**：整个世界状态序列化，存浏览器本地（localStorage 或 IndexedDB），手机和电脑各自一份。`【待确认 Q11】`

## 10. 内容扩展约定

- 内容层标签：main、side、ambient。
- 风格标签：zh、western、mixed，用于控制 6:4 比例。
- 一个内容包只依赖基础包，不互相依赖，可单独启用或关闭。
- 新区域保持高密度：每走约 10 秒能遇到一个可点的东西。

# 附录 A：玩法引擎扩展字段（dev-story 维护，M2）

> 代码契约：`game/src/entities/types.ts`（NPC/反应/指令）、`core/story.ts`（故事）、`core/stimulus.ts`（现象）、`core/sequencer.ts`（演出动作）、`entities/Mech.ts`（机关物）。
> 所有新字段都是**可选**的，旧数据照常运行。拼错字段/未知动作会在 `validateGameplay()` 里报错（控制台 + 开发期校验）。

## A.1 世界标志（flags）
- 任意字符串名 → 数值（缺省 0）。`setFlag/getFlag/hasFlag/addFlag`（`entities/registry.ts`），变化时发 bus `flag:<name>` 与 `flag`。
- 故事自动写：`story:<id>:<step>`、`story:<id>:done`。点灯写：`lit:<propId>`。帽子变身写：`santa`。
- 随存档保存：`allFlags()` / `loadFlags(obj)`。

## A.2 故事（stories.json）
```jsonc
"xiaolan_story": {
  "npc": "xiaolan", "need": 3, "finale": "xiaolan_finale", "title": "story.xiaolan",
  "phase": ["morning","noon"],                 // 阶段锁：只在这些阶段推进（缺省=任意）
  "requires": { "stories": ["laozhou_story"], "flag": "lit:lamp_a", "notFlag": "x" }, // 前置；未满足状态=locked
  "onStart": { }, "onDone": { },               // OnDone，见下
  "steps": [
    // kind: stimulus(旧) | quiet(旧) | event | flag | arrive | near | timer
    { "id":"smell", "kind":"stimulus", "when":{"type":"scent","tag":"bread","min":0.2}, "sense":"xiaolan" },
    { "id":"look",  "kind":"event", "on":"npc:annoy", "evArg":"xiaolan" },
    { "id":"stairs","kind":"flag",  "flag":"story:laozhou_story:done" },
    { "id":"walk",  "kind":"arrive","npc":"xiaolan","at":[30,12],"r":1.2 },
    { "id":"near",  "kind":"near",  "npc":"afu","target":"npc:xiaolan","r":2 },
    { "id":"wait",  "kind":"timer", "secs":8, "requires":["walk"] },
    { "id":"x", "kind":"stimulus", "requires":["a"], "requiresAny":["b","c"], "optional":true,
      "gate":{"phase":"dusk","flag":"f","notFlag":"g"}, "noHint":true, "needQuiet":3, "fail":{...},
      "onDone": { "seq":"seq_id", "set":["flagA"], "clear":"flagB", "event":"bus_event",
                  "order":[{"npc":"adong","kind":"goto","x":20,"y":8,"speed":1.4},{"npc":"adong","kind":"release"}],
                  "emit":{"type":"sound","tag":"bell","intensity":0.8,"radius":8,"duration":3,"at":[10,10]},
                  "say":[{"npc":"adong","key":"line.x","dur":3}] } }
  ]
}
```
- 多个故事**并行**：`StoryManager` 管理全部；一个现象同时喂给所有 active 故事；提示（20/60/120 秒）只给当前"最久没进展"的那一个，避免提示打架。
- 跨故事依赖：用 `requires.stories`（锁定/解锁，解锁发 bus `story:unlock`），或步骤 `kind:'flag'` 读别的故事写的标志。
- `finale`（序列）在 `done 步数 ≥ need` 时触发。`optional:true` 的步骤不计入 need。

## A.3 NPC（npcs.json 扩展）
```jsonc
"afu": {
  "...旧字段不变...": 0,
  "schedule": [
    { "id":"morning_post", "when":{"phase":"morning"}, "route":[[10,4,6],[14,4],[14,9,8]], "mode":"pingpong", "speed":1.0, "wait":[2,5], "pose":"carry", "say":"line.x" },
    { "when":{"flag":"story:afu_story:done"}, "route":[[12,6]], "mode":"stay", "pose":"relaxed", "face":[13,6] }
  ],
  "emit": {"type":"presence","tag":"dog","intensity":1,"radius":5},   // NPC 自身发出的现象，跟随 NPC
  "scale": 0.8, "hideAt":[2.6,9.0], "species":"dog",
  "reactions": [
    { "on":{"type":"presence","tag":"dog","min":0.3}, "do":"flee", "dist":7, "to":"home", "speed":1.7, "say":"line.fear", "secs":4, "cd":8, "when":{"phase":"morning"}, "poll":true },
    { "on":{"type":"scent","tag":"bread","min":0.2}, "do":"approach", "stop":1.2, "arrive":"bus_event_on_arrive", "poll":true },
    { "on":{"type":"light","tag":"lamp","min":0.3}, "do":"lookUp", "secs":3 },
    { "on":{"type":"sound","min":0.8}, "do":"freeze", "secs":2 },
    { "on":{"type":"company"}, "do":"pose", "pose":"hug", "secs":3, "set":"hugged", "event":"hug_evt", "emit":{...} }
  ]
}
```
- 反应 `do`：`none hide listen startle dance flee approach lookUp freeze pose goto`（可用 `registerReaction(id, fn)` 加新类型）。
- 通用条件：`when{phase,flag,notFlag,state}`、`chance`（0–1）、`cd`（冷却秒）、`force`（无视被打断/忙）、`poll`（对**持续型**现象每 0.35 秒复查，用于气味/光/聚集）。
- 日程优先级：`order`（故事/序列下达的指令） > `schedule`（按阶段/标志选第一条满足的） > 旧 `waypoints`。
- 长途寻路：所有行走走 A\*（8 邻接、不切角、拉直路径）；障碍 = `config.blockedTiles`（默认 `['w']`）+ `config.obstacles:[[x0,y0,x1,y1]…]` + `decor` 里 `solid:true` + 动态阻挡（`block` 现象、机关物 `blocks`）。动态阻挡变化后路径自动重规划。
- 指令 `Order`：`goto{x,y,speed,stop,face,pose}` / `follow{target,dist,speed,side}` / `ride{target,ox,oy}` / `stay{pose,face}`；`target` 为实体 id（`npc:xiaomi`、`hat`、`prop:lamp_a`、`mech:bus`、`pt:x,y`）。
- 贴图后缀（存在才用，缺省回退）：`c_<id>_<pose>`、`c_<id>_up`（lookUp）、`c_<id>_scared`（freeze）。
- 烦躁：`irritation` 0–1，bus `npc:annoy(id, idx)`；旧 `annoy` 字段不变。
- 性能：屏外（相机外扩 ~6 格）NPC `lod=1`：不渲染、不查现象、不发特效，但**日程/指令照常推进**；时间复杂度 O(NPC + 活跃现象)。

## A.4 现象（moves.json 的 `emit`，及序列 `emit` 动作的 spec）
```jsonc
"emit": {
  "type":"scent|sound|light|block|company|presence|…", "tag":"bread", "intensity":0.8, "radius":6,
  "duration":0,            // 0=一次性脉冲；>0 持续秒；-1 永久（直到 remove / setEmitter(id,null)）
  "fadeIn":1, "fadeOut":2, // 包络（秒）
  "grow":0.6,              // 半径每秒增长（上限 2×初始，气味扩散）
  "cone":{"dir":[1,0],"arc":0.6}, // 光锥/视线：dir 朝向，arc=cos 半角；被 block 遮挡 ×0.1
  "shape":[3,1],           // block：矩形 w×h（格），同时进入导航阻挡
  "anchor":"npc:afu",      // 跟随实体（NPC 发出的狗味、公交上的引擎声）
  "mover":{...}            // 旧：飞行物
}
```
- **scent**：随风向 `wind{dx,dy,speed}`（`config.windDir`，缺省 `[1,0.35]`）拉长成下风向的椭圆；**light**：锥形 + 视线遮挡；**block**：矩形占位；**company**：持续、被"围观/跟随"类反应读取。
- 声音半径仍乘 `config.soundWeather`（雨/雪天衰减）。

## A.5 机关物（新文件 `mechs.json`，键=id）
```jsonc
"bus": { "tex":"m_bus", "scale":1, "origin":[0.5,0.9],
  "path":[[10,12],[30,12,4],[30,20]], "mode":"loop|pingpong|once", "speed":2.2, "auto":true, "startDelay":0,
  "when":{"phase":"morning"}, "anim":"roll|bob|sway|slide|none", "blocks":[2.4,1.1],
  "carries":["niuniu"], "emit":{"type":"sound","tag":"engine","intensity":0.6,"radius":6},
  "follow":{"target":"npc:adong","ox":0.6,"oy":0.3},   // 轮椅/气球串：跟随实体（与 path 二选一）
  "z":0, "onStop":"bus_stopped" }
```
- 路点第 3 个数 = 停留秒数（到站发 bus `mech:arrive(id,idx)`；停车/终点发 `mech:stop`，开动发 `mech:start`）。
- 纹理缺失时自动生成占位方块，不会崩；`blocks` 的占地随车移动实时更新导航阻挡（公交停在路上=堵路，玩家用招式让它走）。
- 序列控制：`{do:'vehicle', id:'bus', cmd:'start|stop|goto|park|path', to:[x,y], wait:true}`。

## A.6 序列动作（sequences.json）
旧：`lock say wait walk cam(focus) crowd phase sing hat warmth event banner`。**新增**：

| do | 字段 | 作用 |
|---|---|---|
| `bg:true`（任一动作） | | 不阻塞，后台并行；序列首项 `{do:'meta',bg:true}`=整条序列后台运行、不锁玩家、不排队 |
| `parallel` | `lists:[[…],[…]]` | 多条动作列表并行，全部结束后继续 |
| `if` | `flag/notFlag/phase`, `then`, `else` | 条件分支 |
| `runSeq` | `id` | 调用另一条序列 |
| `flag` | `set/clear/v` | 改世界标志 |
| `waitEvent` / `waitFlag` / `waitNpcAt` | `id｜flag`, `timeout` / `npc,at,r` | 等待 |
| `cam` | 新写法 `to:[x,y]｜实体id, zoom, s` | bus `cam:to`；`focus` 旧写法不变 |
| `camPath` | `points:[{to,zoom,s,hold}]` | 依次运镜 |
| `camRelease` / `shake` | `k,s` | 回到跟随帽子 / 震屏 |
| `slowmo` | `scale:0.3, s:1.5, ramp, wait` | bus `time:scale` |
| `subtitle` | `key｜text, dur, style:normal｜big｜final, wait` | bus `subtitle` |
| `audio` | `cue, arg` | bus `audio:cue` |
| `npcDo` | `npc, order｜pose,secs｜face｜hide｜flee｜noReact｜say, wait` | 给某 NPC 下指令/姿态 |
| `emote` | `npc, e` | 表情气泡 |
| `gather` / `release` | `around, who[], r, perRing, hearts, wait, max` | 全城/指定 NPC 同心圆聚集；释放 |
| `vehicle` | 见 A.5 | 机关物 |
| `prop` | `id, move` | 无视冷却触发某物件的招式 |
| `light` | `props[], gap, move` | 依次点亮（写 `lit:<id>`，发 `light:on`） |
| `lightString` | `props[], gap, closed, z, camFollow, zoom` | **终章灯串**：依次点亮并在相邻两盏之间挂出灯泡串（事件 `light:string`），完成发 `light:done` |
| `emit` | `at, spec` | 在某处释放现象 |
| `fx` | `id, at` | 播放注册特效（`sparkle/hearts/notes/ring` 或任何 `registerFx` 的 id） |
| `hatMorph` | `to:'santa', s, at` | **帽子长出身体 → 圣诞老人**（事件 `hat:morph`，结束写 flag `santa`、发 `hat:morphed`） |

扩展：`registerAction(id, (action, ctx)=>…)`；`ctx.host` 为 SeqHost。多条序列同时触发时自动**排队串行**（不会互相打断）。

## A.7 bus 协议（引擎 ↔ 场景/UI/音频）
| 事件 | 参数 | 发出者 → 接收者 |
|---|---|---|
| `cam:to` / `cam:release` / `cam:shake` | `{x,y,zoom,s,ease,target}` / – / `{k,ms}` | sequencer → Game 相机 |
| `time:scale` | `{k,ramp}` | sequencer → Game（慢动作） |
| `subtitle` | `{text,dur,style}` | sequencer → HUD |
| `audio:cue` | `(cue,arg)` | sequencer → music |
| `story:step(storyId,stepId)` / `story:done(id)` / `story:unlock(id)` | | story → HUD/存档/音频 |
| `npc:annoy(id,idx)` | | Npc → 幽默系统 |
| `mech:start/arrive/stop` | `(id[,idx])` | Mech |
| `light:on(propId)` / `light:string` / `light:done` | | sequencer → fx |
| `hat:morph` / `hat:morphed` / `fx:play` / `prop:fired(propId,moveId)` | | sequencer/fx |
| `flag:<name>` / `flag` | `(value)` | registry |

- 单项：`scene.stories.debug()`、`scene.stories.map[id]`（`current()/done/finished/hintTier/lastProgress`）、`npc.debug()`、`scene.stim.debug(now)`、`scene.mechs.debug()`、`scene.fx.debug()`。
- 注入/断言：`setFlag(name,v)` 直接改标志；`scene.stim.emitSpec(spec,x,y,'test',now)` 释放任意现象；`scene.seq.run(id)` 直接播序列；`mech.start()/stop()/goto(x,y)`。
- 不变量建议：NPC 不应站在 `blockedTiles` 上（`hide` 状态除外）；`stim.active.length` 有上限（建议 < 80）；`nav.searches` 每秒增长应 < 30（缓存命中）。

## A.9 补充字段（M2，对应 ENGINE-REQUESTS E3–E12）
- **step.kind 新增**：`count`（`flag`、`min`、`within?`：flag 数值在 within 秒内累计增加≥min）、`combo`（`events[]`、`within?`=20：所有事件都在窗口内发生）。
- **step.hold**（秒）：对 `near`/`arrive`/`flag` 生效，条件需连续保持，离开即清零。
- **reaction.clear**：与 `set` 对应，反应触发时清一个 flag。
- **moves 标志联动**（`entities/registry.ts`，由 Game.useMove 调用）：`moveAllowed(move)`→`{ok,failSay}`（`requires:{flag,notFlag}`）；`applyMoveEffects(move)` 处理 `set/clear/add:{flag,n}`，并按权重抽 `pick:[{w,say,fx,set,event}]` 返回被抽中项。
- **序列简写**：`{"runSeq":"phase_noon"}` 等价于 `{"do":"runSeq","id":"phase_noon"}`。
- **vehicle**：`cmd` 新增 `follow{target,ox,oy,lag?}`、`unfollow`、`park{to}`。
- **gather.who** 中缺失的 NPC：warn 一次并跳过。
