# 07 开发路线

当前阶段：设定讨论，尚未开发。本文档是路线建议，确认后再启动。

## 1. 技术选型（建议）

| 项目 | 建议 | 理由 |
|---|---|---|
| 语言 | TypeScript | 数据 schema 校验和类型提示 |
| 引擎 | Phaser 3（备选 PixiJS） | H5 和手机适配成熟，自带等距和动画支持 |
| 架构 | 轻量 ECS，"现象、感知、状态机"做成独立系统 | 数据驱动，便于扩展 |
| 数据格式 | JSON 或 YAML + schema 校验 | 错误启动时就报出 |
| 地图 | Tiled | 成熟的地图编辑器 |
| 音频 | Web Audio，分层音轨 | 支持动态叠加 |
| 构建 | Vite | 轻、快 |
| 部署 | 静态站点 | 手机和网页直接访问 |
| 调试 | 内置调试面板 | 实时看暖度、现象范围、故事进度 |

## 2. 里程碑

| 里程碑 | 目标 | 验收 |
|---|---|---|
| M0 最小闭环 | 一个小房间、一个 NPC、一个物件、一种现象 | 风铃响，NPC 感知，状态变化，决心满后自己行动 |
| M1 一个完整故事 | 小米整条线，头顶气泡、提示系统、帽子变化 | 从头玩到尾，有搞笑失败 |
| M2 连锁 | 老周的香味影响小蓝 | 现象能跨区域影响另一 NPC |
| M3 世界化 | 区块拼接大地图、昼夜、阶段锁、存档、天气 | 刷新页面后进度保留 |
| M4 补完与沙盒 | 补完 5 条线和终章，加入彩蛋和通关后模式 | 主线约 30 分钟 |
| M5 音频与美术 | 替换占位资源，做音乐分层 | 完整体验 |

M0 和 M1 是对框架的最大验证，出问题时改成本最低。

## 3. M0 任务清单

1. 初始化项目（Vite + TypeScript + Phaser），本地可运行，手机可访问。
2. 定义数据 schema：Stimulus, Move, Prop, NPC。
3. 实现数据加载与启动时校验。
4. 实现等距地图渲染：一个小房间（可用占位瓦片）。
5. 实现帽子：点击地面飘行，无碰撞，有漂浮感。
6. 实现物件点击附身：瞬移动画，一次只附身一个。
7. 实现招式选项和冷却。
8. 实现现象系统：生成、范围、衰减、持续时间。
9. 实现 NPC 感知：对现象的敏感度。
10. 实现 NPC 状态：决心累积与阈值。
11. 实现 NPC 自主行动：决心满后播放"迈出一步"。
12. 实现头顶气泡：显示心情和卡点。
13. 实现烦躁度三档。
14. 实现调试面板：显示现象范围、NPC 决心、烦躁度。
15. 一个简单的音频层：风铃声、完成时的一小段旋律。
16. 手机触控测试（点击、拖动）。

### M0 完成标准

- 玩家附身风铃响铃，NPC 小米有可见反应。
- 新增第二个物件，只改数据，不改代码，即可生效。
- 在手机浏览器上可操作。

## 4. 内容生产流程（框架稳定后）

1. 写故事卡：人物、心结、模板、推荐解法、搞笑失败、隐藏项。
2. 填数据：NPC、物件、Gag、对话。
3. 本地校验脚本检查数据完整性和引用。
4. 试玩调参：提示节奏、决心阈值、烦躁度。
5. 加入内容包，可单独启用。

## 5. 风险

| 风险 | 缓解 |
|---|---|
| 美术量过大 | 角色复用骨架、换色变体；地图瓦片拼接；先占位 |
| 现象系统太复杂导致不可控 | 首版只做 6 种现象和 6 条相互作用，其余后加 |
| 故事太"涌现"导致玩家迷路 | 提示系统加地标颜色，推荐解法保证至少一条路通 |
| 幽默写作成本高 | 先做通用库，Gag 逐步补；设定质量要求每条 20 字以内 |
| 手机性能 | 控制同屏 NPC 数量，粒子可降级 |
| 配乐成本 | 一段主旋律加变奏，不做多首完整曲目 |
